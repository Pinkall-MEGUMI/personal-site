## 0. 先破一个念头："我又不重要，谁会攻击我"

我一开始也是这么想的。被告知三件事之后就不这么想了：

1. **攻击是自动的，不是冲你来的。** 全世界有无数脚本 7×24 小时扫描所有能连上的地址，找已知漏洞。它们不认识你，也不需要认识你。
2. **你的服务器如果被拿去做坏事，你是要负责的。** 网站被人塞了跳转、发垃圾邮件，最后追责到域名所有者。
3. **真正会丢的不是网站，是账号。** 拿到你的 GitHub 就能改你的站，拿到你的 Cloudflare 就能删你的域名。这才是最疼的。

所以安全对个人站来说不是"防黑客大片"，而是三件朴素的事：**别被打垮、别被拿走、别被人当成跳板。**

## 1. 基础课：一个网站在线，靠的是四样东西

先别急着看配置。不理解这四样，后面全是天书。

| 组成 | 通俗理解 | 类比 |
|---|---|---|
| **域名** | 别人要输入的地址，`pinkallspace.com` | 你家的门牌号 |
| **DNS** | 把域名翻译成 IP 地址的"通讯录" | 查号台 114 |
| **托管/服务器** | 真正放文件、对外应答的机器 | 仓库 |
| **HTTPS 证书** | 证明"这个网站真的是你的"，并加密传输 | 带防伪的密封信封 |

我在浏览器输入 `pinkallspace.com`，实际发生的是：

```
① 找查号台（DNS）：pinkallspace.com → 某台服务器的 IP
② 连线 + 验证书（TLS）：确认对面是它自己，建立加密通道
③ 发请求、收网页（HTTP）
```

**记住这三步。** 后面所有安全问题，都落在其中某一步上。

### 顺手学一个反常识

我一直以为「`.com` 在国内会卡，`.cn` 会更快」。这是错的。

- 域名后缀只影响 **第 ① 步**（查号台）
- 真正决定快慢的是 **第 ② ③ 步**：服务器在哪、线路好不好

所以换成 `.cn` 一点用都没有。**决定速度的是服务器位置，不是域名后缀。** 这句话让我少交了一年学费。

## 2. 第一课：DNS 污染（我的网站"明明部署成功却打不开"）

### 现象

我部署成功了，控制台明确显示已经发布，但浏览器就是打不开。

### 排查过程

我把域名拿去查解析结果，对比了三个网站：

| 域名 | 解析到的 IP | 能不能连 |
|---|---|---|
| `github.com` | 正常 IP | ✅ 能 |
| `www.cloudflare.com` | `104.16.124.96` | ✅ 能 |
| 我的 `*.workers.dev` 地址 | `74.86.3.208` + IPv6 `...:face:b00c:...` | ❌ 不能 |

`face:b00c` 这个 IPv6 一看就不对劲——它是 **Facebook 的地址段**，而我的网站跟 Facebook 毫无关系。这叫 **DNS 污染**：查询被中间人截住，返回了一个假地址，浏览器就连到了错误的地方，自然打不开。

### 学到了什么

1. **"部署成功"和"用户能访问"是两件事。** 前者是服务器的事，后者要过 DNS 这一关。
2. **`*.workers.dev` 这类免费子域名在国内经常被污染。** 一旦被污染，你的站等于不存在。
3. **解法是绑一个自己的域名。** 因为 `cloudflare.com` 本身是通的（`104.16.x` 实测可连），换成自己的域名后流量走你域名的 DNS → Cloudflare 节点，就不再经过那个被污染的地址。

### 这一步变成"术语"之后

> **DNS 污染** = 查号台被人篡改，给你一个假号码。
> **应对** = 用自己的真号码（自己的域名），不依赖别人的免费号码。

## 3. 第二课：HTTPS 不只是个小锁头

### 没有它会怎样

不用 HTTPS，你和网站之间的所有内容都是**明文**：你打开哪个页面、提交了什么、Cookie 是什么，链路上任何一跳都能看见，也能改。

### 两个层次，别混

| 层次 | 是什么 | 谁提供的 |
|---|---|---|
| **加密** | 内容变成密文，中途看不懂 | TLS 证书（Cloudflare 免费给） |
| **强制** | 浏览器如果有明文的 `http://` 入口，自动踢到 `https://` | 两处：Cloudflare 的 `Always Use HTTPS` + 我自己的代码兜底 |

### 踩过的坑

我先在代码里写了"如果是 http 就跳转到 https"，**没生效**。原因是 Cloudflare 会在边缘把我的请求在内部就规范成 https，代码里根本看不到原始协议。

最后用 Cloudflare 自己的开关解决。页面在这：

```
域名 → SSL/TLS → Edge Certificates → Always Use HTTPS
```

打开后，任何 `http://` 访问都会返回 **301**（永久跳转）到 https。

### 现在的额外一层：HSTS

我还在响应头里加了：

```
Strict-Transport-Security: max-age=31536000
```

意思是：**"未来一年内，这个域名只准用 HTTPS 访问。"** 浏览器会记住。这样连"先发一次明文请求再跳转"的那个空窗期都没了——中间人没机会在你被跳到 https 之前截一次明文。

## 4. 第三课：安全响应头 = 随网页附带的"注意事项"

这是今天做的最"看不见"的一件事，也是我最需要解释的。

### 响应头是什么

服务器返回网页时，会在正文之外附一张小便签，叫**响应头**。浏览器会读这张便签，决定"怎么对待这个网页"。写对了，等于给浏览器下了一串安全指令。

我在项目里加了一个文件 `public/_headers`（Cloudflare 会自动读它，不会把它当普通文件暴露出去），内容是：

```
/*
  X-Content-Type-Options: nosniff
  X-Frame-Options: DENY
  Referrer-Policy: strict-origin-when-cross-origin
  Permissions-Policy: accelerometer=(), camera=(), geolocation=(), ...
  Cross-Origin-Opener-Policy: same-origin
  Cross-Origin-Resource-Policy: same-origin
  Strict-Transport-Security: max-age=31536000
  Content-Security-Policy: default-src 'self'; script-src 'self' 'unsafe-inline'; ...
```

下面逐个翻译成人话。

### ① `X-Frame-Options: DENY` —— 防点击劫持

**没有它会怎样**：别人可以写一个网页，中间嵌一个透明 iframe 盖着你的网站，诱导你点"领取奖品"，实际点的是你网站上的按钮。

**类比**：不许别人在你店门口套一层玻璃罩，然后当成自己的店骗客人。

### ② `X-Content-Type-Options: nosniff` —— 防 MIME 嗅探

**没有它会怎样**：浏览器有时会"自作聪明"，猜文件类型。你把一个 `.json` 当数据返回，它可能把里面的内容当**脚本执行**。

**类比**：说明书就按说明书用，别拿它当炸药包。

### ③ `Content-Security-Policy` —— 最狠的一条，白名单门卫

CSP 规定：**这个页面只许加载哪些资源。**

我设的 `default-src 'self'` 意思是：只许加载我自己域名下的东西。任何外部脚本、外部字体、外部图片，一律不加载。

**没有它会怎样**：如果哪天有人找到了往你页面注入内容的口子，第一件事就是塞一个 `<script src="http://黑客的服务器/x.js">`，你的访客就被接管了。CSP 让这种注入**执行不了**。

**代价**：我给内联脚本留了 `'unsafe-inline'`（因为主题切换按钮必须内联），所以这一条不是最严格版。但对一个没有任何第三方资源的静态博客来说已经足够。

### ④ `Referrer-Policy: strict-origin-when-cross-origin` —— 别乱说我从哪来

**没有它会怎样**：你从我的站点了外链，浏览器会把完整的来源地址报给对面。如果来源页带敏感参数，就泄露了。

这条设成"跨站时只说域名，不说具体路径"。

### ⑤ `Permissions-Policy` —— 关掉用不到的硬件权限

我的博客不需要摄像头、麦克风、定位、支付、USB。全部显式关掉。即使页面被注入代码，也调不动这些设备。

**类比**：店里不用的设备，电源直接拔了。

### ⑥ `Cross-Origin-Opener-Policy` / `Cross-Origin-Resource-Policy`

防止别的网站开窗口"抓住"我的页面做跨站攻击，也防止我的资源被外部站点盗用。

### ⑦ 缓存头（顺带的性能优化）

```
/_astro/*      Cache-Control: public, max-age=31536000, immutable
/search.json   Cache-Control: public, max-age=0, must-revalidate
```

带哈希的文件名内容永远不会变，可以缓存一年；搜索索引会变，每次都要校验。

## 5. 第四课：爬虫 —— robots.txt 是君子协定，不是锁

我问"怎么防爬虫"时得到的最有用的一句话是：

> **`robots.txt` 只挡守规矩的。** Google、百度会遵守；恶意采集器根本不看。

所以它只能算"礼貌请求"，不是防护。真能生效的只有两类：

### ① User-Agent 黑名单（免费版真正能用的功能）

在 Cloudflare **Security → Settings → User agent blocking** 里加一条规则，表达式：

```
(http.user_agent contains "SemrushBot") or (http.user_agent contains "AhrefsBot")
or (http.user_agent contains "MJ12bot") or (http.user_agent contains "DotBot")
or (http.user_agent contains "BLEXBot") or (http.user_agent contains "DataForSeoBot")
or (http.user_agent contains "PetalBot") or (http.user_agent contains "Bytespider")
```

动作选 **Block**。

**为什么只拦这些**：它们都是 SEO 分析、营销数据公司的爬虫，每天扫全站、对你毫无价值，纯消耗带宽。

**为什么不拦 `curl` / `python` / `node`**：太宽了，会误伤网站监控、RSS 阅读器，还有我自己写的自检脚本。

**千万别拦 `Googlebot` / `Baiduspider`**：拦了你的站就不被搜索引擎收录了。

### ② 频率限制（Rate limiting）

挡不住"是谁"，但能挡"来多快"。以后 Agent 接口上线，要加一条：

| 项 | 值 |
|---|---|
| 路径 | `/api/chat` |
| 阈值 | 10 次 / 1 分钟 / IP |
| 动作 | Block |

**为什么重要**：Agent 接口背后是**按量付费的模型 API**。别人刷你的接口，刷的是你的钱包。这条规则比在代码里写计数器可靠得多（边缘的计数是全局的，代码里的计数只在一个进程内有效）。

### ③ 心态

我一度以为需要"彻底防住采集"。结论是**不值得**：

- 你写的是公开博客，本来就是要被读的
- 采集者会换 IP、会伪装浏览器，纯技术手段很难彻底防
- 真正的损失只有带宽，而 Cloudflare 免费额度扛得住

**要防的不是"被读"，是"被打垮"和"被偷账号"。**

## 6. 第五课：静态站为什么"没有病毒面"

我原本以为要装个"查毒扫描"，被纠正了：

> **纯静态站没有病毒面。** 没有上传、没有数据库、没有后端进程、没有 WordPress 插件——没有能被植入"会执行的代码"的地方。

那"防病毒"在这个语境下对应什么？三件更真实的事：

| 真实风险 | 说明 | 防护 |
|---|---|---|
| **账号被盗** | 拿到 GitHub 或 Cloudflare 就能改站、删域名 | 2FA（下一节） |
| **依赖被投毒** | 项目依赖几十个开源包，某个包被植后门，构建时把坏代码带进去 | 依赖审计、只从官方源装 |
| **密钥泄露** | 把 API Key 写进代码、推到公开仓库，几分钟内被爬虫盗刷 | 只放服务端环境变量 |

### 我实际查了依赖漏洞

```
升级前：14 条（1 critical / 12 high / 1 low）
升级后：12 条（1 critical / 10 high / 1 low）
```

看起来吓人，但要学会读：

- 那条 critical 是**「AVIF 图片优化的远程代码执行」**——我的站**一张图片都没有**，也不用图片优化服务，这条打不到我
- 其余多是**「未转义属性名导致的 XSS」**——我的页面全是我自己写的静态内容，不渲染任何用户输入
- 有一条是**「Windows 本地开发服务器任意文件读」**——只在我本机跑开发服务时才有意义

**结论：漏洞是真的，但在我的用法下不可达。** 为不可达的漏洞把框架大版本升级，反而有把站搞坏的风险——这个取舍要讲清楚，不能一味追"零漏洞"。

### 学到的一句话

> **风险 = 漏洞 × 可达性。** 只看漏洞数量会自己吓自己。

## 7. 第六课：2FA 是唯一"丢了就真丢"的防线

今天所有措施里，**最重要的不是任何一行配置，而是双因素认证（2FA）**。

### 为什么

上面所有防护（响应头、CSP、HTTPS、爬虫拦截）都在防"外面的人打进来"。但**如果你的账号密码泄露**，攻击者是从正门走进来的——他有合法身份，所有防护对他是透明的。

拿到 GitHub 就等于拿到你的源代码仓库，可以推一版恶意内容；
拿到 Cloudflare 就等于拿到你的域名和托管，可以删站、可以劫持。

### 类比

- 密码 = 钥匙（可以被复制、被偷、被猜）
- 2FA = 钥匙 + 指纹（光有钥匙进不去）

### 要做的事

| 平台 | 位置 |
|---|---|
| GitHub | Settings → Password and authentication → 开 2FA |
| Cloudflare | Profile → Authentication → 开 2FA |

手机装个验证器 App（Google Authenticator / Microsoft Authenticator / 1Password 都行），扫码绑定，**同时把恢复码打印或抄下来存好**——手机丢了就是这个码救你。

## 8. 第七课：加一个"漏洞报告渠道"

我加了一个很不起眼但很专业的东西：

```
public/.well-known/security.txt
```

内容：

```
Contact: mailto:（我的邮箱）
Expires: 2027-12-31T00:00:00.000Z
Preferred-Languages: zh, en
```

访问 `https://pinkallspace.com/.well-known/security.txt` 就能看到。

**它的作用**：安全研究者发现你站的问题时，按这个文件里的联系方式报给你，而不是直接公开。这是行业惯例，成本为零。

有意思的是，Cloudflare 控制台里也有一个 `Security.txt` 开关——**我保持关闭**，因为我已经用自己的文件了，打开反而会被它的生成版本覆盖。**同一个功能不要开两套。**

## 9. 第八课：怎么证明"真的生效了"，而不是"我以为生效了"

这是今天最有价值的方法论。我写了一个自检脚本：

```bash
npm run verify
```

它会**真的去请求线上站点**，逐项检查：

```
路由状态    14/14 ✓   （每个页面都返回 200）
内容检查     6/6  ✓   （canonical、RSS、robots、sitemap 指向正确）
接口与安全   3/3  ✓   （/api/chat 通、HTTP 301 跳转、404 页正常）
安全响应头   8/8  ✓   （CSP/HSTS/nosniff/... 全部实际存在）
全部通过 ✅
```

**为什么重要**：配置项写进文件，不等于线上生效了。中间隔着一层构建、一层部署、一层缓存。**唯一可靠的判断是去请求它、看返回。**

今天就靠这个抓出两次"以为改好了其实没生效"：

1. 改了域名配置，推了代码，线上还是旧地址（那次构建根本没触发）
2. 加了 HTTPS 跳转代码，自检显示还是 200（Cloudflare 在边缘已经把协议规范了）

**没有自检脚本，这两个问题我都会以为"已经修好了"。**

## 10. 今天的完整问答整理

按时间顺序，把我问的和我学到的记下来。

### Q1：我想要个自己的网站，最快的路线是什么？

**答**：静态站 + 免费托管 + Markdown 写作，不需要数据库、不需要买服务器。
**学到**：**"网站"不等于"要一台服务器"。** 我这种内容站，构建出来的就是一堆 HTML 文件，放哪儿都能跑。

### Q2：`localhost:4321` 打不开？

**答**：那个端口上根本没有进程在监听——开发服务器没启动（或已经退出）。
**学到**：**"打不开"先分两类**：是本地服务没起（问题在你电脑），还是线上服务挂了（问题在服务器）。别一上来就怀疑代码。

### Q3：怎么在 GitHub 建仓库、怎么推上去？

**答**：网页建空仓库（**不要**勾 README/gitignore，否则会和本地冲突）→ 本地 `git push` → 第一次会弹浏览器授权。
**学到**：`git` 只是本地存档，`push` 才是上传。授权页**有有效期**——那个页面过期了按钮就点不动，得重新触发一次新的。

### Q4：授权页的按钮点不了？

**答**：不是按钮坏了，是我之前那次 `git push` 已经退出，那个授权链接作废了。
**学到**：**很多"点不动"是超时，不是故障。** 重新走一遍流程即可。

### Q5：控制台里找不到 `Workers & Pages`？

**答**：新版控制台把它归到了 `Compute` 下面。
**学到**：云平台界面会改版，**文档里的路径可能已经过时**。更稳的办法是按 `Ctrl + K` 用全局搜索。

### Q6：`.com` 在国内会卡吗？有必要上 `.cn` 吗？

**答**：都不会因为后缀变快或变慢。速度取决于服务器位置和线路。
**学到**：**域名后缀不参与"传输"这件事**，它只参与"解析"。而且免备案跟后缀无关——备案跟**服务器在不在大陆**有关。

### Q7：我只能用支付宝和银联，Cloudflare 买不了域名怎么办？

**答**：Cloudflare 只收国际卡。改成**在阿里云买域名（支付宝）+ 把 DNS 托管迁到 Cloudflare**。
**学到**：**"注册商"和"DNS 托管商"是两件事**，可以拆开。名字在谁那儿不重要，谁来解析才决定知不知道去哪。

### Q8：怎么给网站做防爬虫、防病毒？

**答**：静态站没有病毒面；能做的防护集中在"安全响应头 + 强制 HTTPS + 爬虫 UA 黑名单 + 频率限制 + 2FA"。
**学到**：**先分清"表演型安全"和"真的有用"**。装一堆插件不如开 2FA 加几行响应头。

### Q9：为什么 `Bot Fight Mode` 搜不到？

**答**：新版控制台把它合并了，部分账户已经没有这个开关。而且 `Security level` 也已改成全自动。
**学到**：**不是所有"教程里的开关"都还在。** 找不到就说明它被产品重构掉了，别硬找。

## 12. 三句话总结

1. **安全不是装个插件，是把每一层的默认值改对。** 响应头、强制 HTTPS、关掉不用的权限，都是"改默认值"。
2. **风险 = 漏洞 × 可达性。** 别被漏洞数量吓到，先问"它打得到我吗"。
3. **所有"我以为生效了"，都要靠一次真实请求来证伪。** 这是我今天学到的、比任何配置都值钱的一条。
